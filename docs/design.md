# 디자인

> 이 문서가 답하는 질문: 어떻게 보이는가. 색·글꼴·간격은 숫자로. 화면 만들 때 `@docs/design.md`.
> 토큰의 원본은 `frontend/src/app/globals.css` `@theme`. 여기와 어긋나면 globals.css를 따르고 이 문서를 고친다.

## 원칙

- **홈에서 스크롤 없이 전부.** 첫 화면 안에 검색·기능·실시간 매물이 다 들어간다. 화면 높이에 맞춰 늘고 줄어드는 레이아웃(`h-dvh` + flex), 고정 px 높이로 넘치지 않게.
- 반응형 하나의 페이지. 데스크톱(≥1024)과 모바일(<768)이 같은 컴포넌트를 다른 배치로.
- 다크 모드 없음 (1단계).
- 카드 남발 금지. 구분선과 여백으로 나누고, 카드(테두리+흰 배경)는 폼·타일·메뉴에만.
- 중앙 큰 제목·히어로·플로팅 버튼 없음. 기능부터 바로.
- 아이콘은 선 아이콘(stroke 1.8, 24 viewBox), 인라인 SVG. 이모지 금지. 예외: 판매·구매 아이콘(홈 아이콘 줄·헤더 앱 메뉴)은 2톤 일러스트, 앱 메뉴 버튼(∷)은 채운 점 9개 (아래 규격).

| `line` | `#DED2EA` | 카드·입력 테두리 |

## 글꼴

| 역할 | 글꼴 | 굵기 |
|---|---|---|
| 본문·제목 | Noto Sans KR (next/font/google) | 400 / 500 / 700 |
| 숫자·가격·모델명 | IBM Plex Mono, `tabular-nums` | 500 / 600 |

크기 단계 (px): 11 캡션 · 12 보조 · 13 본문(목록) · 14 본문 · 15 강조 · 17 검색 입력 · 18 로고 · 20 제목.
줄 간격 1.5. 한글 `word-break: keep-all`.

## 간격·모양

- 간격 스케일: 4, 6, 8, 10, 12, 16, 20, 24, 28.
- 페이지 옆 여백: 데스크톱 24, 모바일 16.
- 모서리: 입력·버튼·카드 6, 타일 10, 아이콘 원 12, 로고 마크 6.
- 테두리 1px `line`. 검색창만 2px `primary`.
- 그림자 없음 (시안 뷰어 제외).

## 브레이크포인트

| 이름 | 폭 | 홈 배치 |
|---|---|---|
| 모바일 | < 768 | 세로 1열. 하단 탭바. 문구 + 검색창 + 판매·구매 아이콘 줄(두 줄)을 가운데 |
| 태블릿·데스크톱 | ≥ 768 | 문구 + 검색창 + 판매·구매 아이콘 줄(최대 폭 880)을 화면 가운데(조금 위) — 구글 첫 화면처럼. 같은 아이콘이 헤더 앱 메뉴(∷)에도 있다 (2026-10-19 둘 다). 실시간 목록·구매대행·경매 자리는 없음. 스크롤 없음 |

## 컴포넌트 규격

**타일 큐 (화면 분할)** 모든 화면 전환을 하나의 큐로 (스펙 `docs/superpowers/specs/2026-10-01-tile-queue-design.md`). 폭 768 이상만 분할: 1칸 전체 → 2칸 1:1 → 3칸 왼쪽 1/2 · 오른쪽 위 1/4 · 오른쪽 아래 1/4 (읽는 순서 = 오래된 순서, 새 칸은 오른쪽 아래, 가득 차면 왼쪽 칸이 빠지고 당겨짐). 칸 사이 구분(2026-10-21 — 칸이 서로 꽉 차 경계가 안 보인다는 사용자 의견): 칸 사이 간격 8 + 바깥 여백 8 에 `line-2` 바탕이 비치고, 칸마다 1px `line` 테두리·모서리 10. iframe 안(framed)에는 적용하지 않는다. 2칸 이상이면 모든 칸 오른쪽 위에 닫기(28 원, 흰 배경, 1px `line`, 호버 `primary` 테두리). 로고는 항상 홈 전체화면.

**헤더** 높이 56 (모바일 52). 배경 `primary`, 글자 흰색, 내비 `on-primary`. 로고 = 초록 사각(28, radius 6) + 흰 칩 아이콘 + "커널마켓" 18/700. 오른쪽 앱 메뉴(∷) · 로그인(초록 버튼 60×34). 모바일은 항목 사이 간격 12(데스크톱 28) — 360 폭에서도 로그인 버튼이 잘리지 않게. 회원가입 버튼은 없다 — 로그인 화면의 개인·기업 탭에서 가입 (2026-10-13). 로그인은 **별도 페이지**로 이동 (모달 아님). 헤더는 루트 레이아웃에 한 번만 두고, 로그인·가입 화면과 분할(2·3칸) 상태에서도 같은 링크를 유지한다 (로그인 상태면 그 자리에 사용자 메뉴).
- 사용자 메뉴: 닉네임 첫 글자 원 36(누르는 영역 44), 15/700. 개인 = `primary-soft` 면 + `primary` 글자, 사업자 = `primary-dark` 면 + 흰 글자 + 흰 테두리 2(보라 헤더 위에서 구분). 누르면 오른쪽 정렬 메뉴(폭 224, 흰 배경 + 1px `line`, 그림자 없음): 맨 위 닉네임 14/700 말줄임 + 배지(높이 20, radius 5, 11/600 — 개인 `primary-soft`/`primary-dark`, 사업자 `primary-dark`/흰색) · 구분선 · 마이페이지 · 내 활동내역 · 내 거래이력 · 구분선 · 로그아웃 (2026-10-29). 로그아웃 실패 시 메뉴를 닫지 않고 아래에 `down` 12 문구. 이메일·전화·실명은 보이지 않는다.

**마이페이지** (`/my`, 로그인 필요) 다른 폼 화면과 같은 틀(최대 폭 720, 제목 20/700 + 보조 13, 흰 카드 안쪽 20/24). 카드 위쪽 사용자 칸: 이니셜 원 56 + 닉네임 17/700 + 배지, 아래 `line-2` 구분선. 그 아래 바로가기 카드 둘(내 활동내역·내 거래이력, 2026-10-29): 1px `line` + radius 6, 안쪽 16/14, 제목 15/700 + 설명 13 `ink-2`, 호버 `primary` 테두리 + `bg` 배경, 칸 폭 576 이상이면 두 칸. 바로가기는 마이페이지 칸 자체를 그 화면으로 바꾼다(옆 칸에 쌓지 않음, 2026-10-19).

**내 활동내역** (`/my/activity?tab=requests|sales|purchases`, 기본 requests, 로그인 필요, 2026-10-29) 제목 "내 활동내역" 20/700 + 그 아래 탭 [요청 | 판매 | 구매](높이 34, 1px `line` radius 6, 선택 칸 `primary-soft`/`primary-dark` 500 — 검색 범위 탭과 같은 모양). 탭은 링크라 같은 칸에서 바뀐다(칸을 더 쌓지 않음). 요청 = 받은 견적·구매요청(`TradeList` 판매자용, 진행 중만), 구매 = 보낸 견적·구매중(`TradeList` 구매자용, 진행 중만), 판매 = 아래 내 판매글. 확정된 거래는 여기 없고 내 거래이력에 있다. 옛 `/my/listings`·`/my/sales`·`/my/purchases` 는 이 화면으로 redirect.

**내 거래이력** (`/my/history?tab=all|buy|sell`, 기본 all, 로그인 필요, 2026-10-29) 제목 + 탭 [전체 | 구매 | 판매](같은 모양). 구매확정된 거래만 최신 확정순, 페이지 번호. 표(칸 폭 576 이상): 확정일시(`yyyy-MM-dd HH:mm` mono)·구분(전체 탭만)·상품명·상대 닉네임·단가·수량·금액(mono, 오른쪽 정렬, 금액 700). 좁은 칸은 카드(상품명 + 구분 / 일시·상대 / 단가 × 수량 = 금액). 비면 "아직 확정된 거래가 없어요". 이메일·전화는 없다.

**내 판매글** (내 활동내역 판매 탭) 검색 결과 화면(아래)과 같은 틀·폭(최대 1200)·검색창·필터 바·표/카드·페이지 번호. 다른 점: 제목은 "내 활동내역"과 탭 줄 아래에, 체크박스·[견적 요청]·[구매] 없음, 거래상태 기본값 "거래 중"(2026-10-30 "전체"에서 바꿈 — 활동내역은 진행 중 기준, 거래완료 글은 필터로), 표 맨 오른쪽에 구매요청 건수 열. 표·카드에 [수정]은 없다 — 수정은 상세의 [수정]에서만(2026-11-02 사용자 지시). 글이 하나도 없으면 "등록한 판매글이 없어요" + [판매상품 등록하기].

**행 안 수정** — 없앴다(2026-11-02). 내 판매 표에서 바로 고치지 않고 상세 → [수정] 화면에서 고친다.

**내 구매목록** (내 활동내역 구매 탭, 진행 중만) 표/카드·페이지 번호는 내 판매글과 같은 틀. 행: 상품명·판매자 닉네임·주문량·단가·금액·납품희망일·상태, `구매요청` 행에 [거래완료]·[취소](각각 확인 창). 취소하면 행이 지워져 줄이 빠진다(2026-10-20 — "취소" 배지 없음). 409·404 면 목록을 다시 읽는다.
- 견적 줄(2026-10-21 갱신): 단가 칸은 희망단가를 크게, 등록단가를 아래/곁에 작게("등록 …") — 한 줄에 `수량 × 등록 → 희망 = 금액`으로 이으면 읽기 어려워 카드에선 수량·희망·금액을 줄로 나눈다. 납품희망일은 "-". 상태 배지 `견적요청`(`green-soft`/`green`)·`수락됨`(`up`)·`거절됨`(`down`). 구매자: `견적요청` [취소], `수락됨` 채운 [구매](구매 모달이 그 매물로 열리고, 확인하면 **같은 줄**이 `구매요청`으로 바뀐다 — 새 줄 없음, 견적서 한 건 = 한 행, 2026-10-21), `거절됨` [재요청](견적 모달 — 서버가 같은 행을 덮어씀)·[취소]. 판매자: `견적요청` [수락]·[거절], 답한 뒤엔 버튼 없음. 거래번호(ID)는 화면에 보이지 않는다(사용자에겐 의미 없음). 버튼은 `lib/tradeActions` 가 정한다.

**견적 모달** (`QuoteDialog`, 검색 결과 [견적 요청]·상세 [견적 요청]) 최대 폭 `max-w-xl`, 구매 모달과 같은 틀(낮은 칸에서 여백 축소 + 모달 안 스크롤). 매물마다 1px `line` 카드: 상품명 14/700 + 등록단가·재고·최소/단위 12 `ink-2` mono, 아래 희망단가·수량·납품희망일 3열(좁으면 1열, 납품희망일 기본값은 제공가능일 — 2026-10-27) + 비고. 보낼 수 없는 매물(내 매물·거래완료·재고 부족)은 아래 "보내지 않는 매물" 목록에 이유만. 버튼 [닫기] · [견적 요청 N건 보내기](모든 줄이 맞아야 켜짐). 성공하면 결과 팝업 + [내 구매목록].

수락된 견적 줄(2026-11-02): 구매자 [구매]·[취소], 판매자 [취소]. 수락하면 수량이 묶이므로 양쪽이 풀 수 있다. 견적에서 연 [구매] 모달은 수량 칸이 읽기 전용(수락된 수량)이고 금액은 수락 단가.

**받은 구매요청** (내 활동내역 요청 탭, 진행 중만) 같은 목록 컴포넌트(`TradeList`)의 판매자용: 구매자 닉네임·요청사항, `구매요청` 행에 [취소], 견적 줄(`견적요청`)에 [수락](채움)·[거절](각각 확인 창 — 수락은 "매물 단가가 바뀌고 다른 구매자에게도 그 가격"을 알린다). 표 위에 [모든 견적요청 보기](외곽선 버튼, 2026-11-03)가 있고 누르면 모달(max-w-3xl)이 받은 견적요청 전부(오래된 순 30건)를 같은 상품끼리 묶어 보인다 — 묶음 머리(`bg` 배경)에 상품명·재고·요청 합계(재고를 넘으면 `down` 색 + 안내), 줄에 구매자·수량·희망/등록 단가·납품희망일·요청사항과 [수락](채움)·[거절]. 위에 [모두 수락 (N)](채움)·[모두 거절 (N)]. 처리한 줄은 회색 "수락됨/거절됨", 실패는 줄 아래 `down` 색 사유. `?reg=` 면 그 매물만 + [전체 보기]. 내 판매글의 "구매요청 N건"(0이면 "-")이 여기로 연다. 세부는 `docs/superpowers/specs/2026-10-15-purchase-design.md`.

**검색** 높이 56 (모바일 44). 흰 배경, 2px `primary` 테두리, radius 8. 왼쪽 카테고리 `select`(112px, `primary-soft` 배경 — 카테고리 마스터 미정으로 보류, 지금은 숨김) · 돋보기 · 입력 17px · 오른쪽 검색 버튼(104px, `primary`, 흰 16/700). 아래 "인기 검색" 텍스트 링크 한 줄, 중앙 정렬. 최대 폭 880. 위에 한 줄 문구(20/700, 모바일 17, 중앙). 히어로가 아니라 한 줄이 전부.

- 남의 매물 주소로 들어오면 폼 대신 "내 매물만 수정할 수 있어요" + 상세로 돌아가기.

**판매정보 추가등록** (스펙 `docs/superpowers/specs/2026-10-06-listing-edit-extra-design.md`) 홈 "판매정보 추가등록" 아이콘 → `/listings/extra`(고르기) → `/listings/{userId}/{regDate}/extra`(입력). 둘 다 매물 등록 폼과 같은 틀(폭 720, 흰 카드, 라벨 왼쪽).
- 고르기: 내 매물 목록 한 줄 = 상품명(말줄임) · 제조사·상품번호(mono) · 등록일 · 칩 "보증·서류 N/5"(채운 게 있으면 `primary-soft`, 없으면 `line-2`). 호버 `bg`. 아래 [더 보기](outline 34). 빈 상태 "등록한 매물이 없어요" + 등록 링크.
- 입력: 위에 상품명·제조사(읽기 전용). 보증기간 드롭다운(없음·1·3·6·12·24·36개월), 불량지원 드롭다운(없음·대체·환불), 대체품·테스트리포트·정품인증서 파일 칸(PDF·JPG·PNG, 단일 파일 업로더). 이미 채운 값은 미리 채워 보이고 ×로 비운다. 옛 보증 일수(365)는 가까운 개월(12)로 보인다.
- [저장] 44 `primary` 전체 폭. 바꾼 칸이 없거나 업로드 중이면 비활성. 바뀐 칸만 PATCH, 성공하면 상세로.
- 상세의 내 매물 버튼: [수정] [판매정보 추가] [삭제].

**모바일 하단 탭바** 높이 60. 홈 · 매물 · 등록(`primary` 원 40) · 내 정보. 활성 `primary`, 비활성 `ink-2`. 글자 10px.

**버튼** 기본 34px, 큰 것 40. `primary` 채움+흰 글자 / 초록 채움+흰 글자 / 텍스트. 비활성은 40% 투명.

**뱃지** 높이 20, radius 5, 11/600. 사업자 `primary-soft`/`primary-dark`, 개인 `line-2`/`ink-2`.
