## 2026-09-21 계정 데이터 모델 세부 (data-model.md 1절) [대체됨 → 2026-09-28 단일 users]

- 일반·소셜·기업을 `users` 한 테이블(kind)에. 로그인 수단은 nullable 컬럼 + `social_accounts`. 기업 로그인은 biz_no → owner → user. 이유: 권한·채팅·매물이 전부 user_id 를 가리켜야 해서 주체 테이블은 하나가 단순.
- 가입 전 인증 결과(본인인증·사업자·소셜 프로필)는 Redis 30분. 미완료 가입이 DB 에 안 쌓임.
- 관리자 시드는 환경변수로 앱 시작 시 1명 + 첫 로그인 후 비밀번호 변경 강제. 마이그레이션에 해시 금지.
- 탈퇴 후 재가입 제한 없음. `identity_verifications` 하드 삭제 (파기 의무 — soft delete 규칙의 예외).
- 닉네임 유일은 personal 만. 기업은 기업명 그대로.
- 이름·휴대폰·CI·DI·소셜 이메일은 컬럼 암호화(AES-256-GCM, `AttributeConverter`, 키는 .env). 검색용 sha256 해시 컬럼 별도. 이유: 법적 의무는 아니지만 유출 시 피해가 커서. 비용은 컨버터 하나.
- 재검토: 재가입 악용 사례 → 30일 제한(CI 해시 보관). 기업 사용자 초대 요구 → organization_members.member.

## 2026-09-21 Docker 없는 PC: 테스트는 내장 Postgres (zonky), 운영·CI 는 그대로 Docker [대체됨 → 2026-09-23 Docker 고정]

- 상황: 개발 PC(교육용)에서 Docker Desktop 도, Postgres 직접 설치도 불가. `./gradlew test` 가 Testcontainers 만 쓰면 로컬에서 아무것도 검증 못 함.
- 결정: `backend/src/test/.../TestInfraConfiguration` 이 Docker 를 감지해 **있으면 Testcontainers(pgvector·redis 이미지), 없으면 `io.zonky.test:embedded-postgres`** 로 실제 Postgres 16 바이너리를 테스트 중에만 띄운다. 테스트 코드는 한 벌, DB 만 갈아 끼움. 운영·docker-compose·CI 는 변경 없음.
- 대안과 안 고른 이유: H2 내장 DB — 부분 유니크 인덱스·`timestamptz`·`bytea` 등 우리 스키마가 쓰는 Postgres 기능이 없어 마이그레이션이 안 돌거나 두 벌이 됨. 별도 "도커 없는 브랜치" — 나중에 옮기는 게 곧 머지 충돌. Postgres zip 설치 — PC 정책상 불가.
- 한계: 내장 Postgres 에는 **pgvector 확장과 Redis 가 없다.** 그걸 쓰는 테스트(상품 임베딩, refresh 토큰)는 로컬에서 못 돌고 CI(Docker) 에서만 검증된다. 로컬 초록 ≠ 완료. CI 초록이 완료.
- 제거 조건: Docker 를 쓸 수 있게 되면 `build.gradle` 의 zonky 의존성·BOM 과 `TestInfraConfiguration` 의 `DockerUnavailable` 경로를 지운다. `docker compose up` 후 코드 변경 없이 그대로 동작하므로 "옮기는" 작업은 없다.
- **2026-09-22 덧붙임 — Redis 도 같은 방식.** 인증(refresh 세션·로그인 잠금)이 Redis 를 쓰는데 로컬에 없어서 `com.github.codemonstur:embedded-redis`(테스트 전용, Windows 바이너리 포함)를 Docker 없을 때만 띄운다. 사용자 결정: "일단 오늘만 이 계획으로, 도커 되면 뺀다". 제거 시 지울 것: `build.gradle` 의 `embedded-redis` 한 줄, `TestInfraConfiguration` 의 `embeddedRedis`·`embeddedRedisProperties` 빈. 이제 로컬에서 못 도는 건 pgvector 를 쓰는 테스트만.

## 2026-09-28 파일 저장소는 구현 시 결정, MinIO는 일단 제외 [대체됨 → 2026-10-02 로컬 디스크]

- 결정: 현 단계 Compose·Caddy·환경설정에서 MinIO를 제거한다. 이미지·사업자등록증·견적서 업로드가 구현될 때 요구사항과 운영 비용을 보고 저장소를 선택한다.
- 이유: 현재 백엔드에는 실제 파일 저장 연동이 없고, MinIO 이미지를 받지 못해 전체 Compose 기동까지 막았다. 지금 띄워둘 실사용 기능이 없다.
- 재검토 조건: 파일 업로드 API를 구현하기 시작할 때. DB에는 계속 URL이 아닌 저장소 키만 둔다.

## 2026-10-01 홈: 기능 타일 8개 → 판매·구매 아이콘 묶음, 실시간 목록은 아래로 [대체됨 → 2026-10-13 홈은 검색만, 아이콘은 헤더 앱 메뉴]

- 결정: 홈 위쪽은 문구·검색·판매 4 + 구매 3 아이콘(글씨·카드 없음)을 가운데에 두고, 실시간 구매요청·판매매물은 아래 2칸으로 내린다 (데스크톱 7 : 3 배치 폐기). 기존 타일 중 카테고리·시세·사업자 등록·AI·채팅은 홈에서 뺐다 (헤더 메뉴는 그대로).
- 아이콘은 선 아이콘 규칙의 예외로 2톤 일러스트(연한 면 + 선 + 배지). 사용자가 "이미지 느낌"을 원했고, 판매 보라·구매 초록 구분은 유지.
- 목록은 칸에 들어가는 행 수만 보여주고 스크롤하지 않는다 (사용자 지시. `ResizeObserver`로 높이를 재서 자름). 대안이었던 목록 안 스크롤은 탈락.
- 파일(엑셀·PDF·이미지) 선택은 즉시 확장자·크기만 검사하고 "준비 중" 안내. 저장소 미정(09-28)이라 업로드는 업로드 기능 구현 때. 이동 경로는 임시.
- 재검토 조건: 판매·구매 화면이 생겨 경로·흐름이 정해질 때.

## 2026-10-01 로그인·가입 분할: 왼쪽 홈 칸 닫기, 닫으면 칸을 쌓지 않음 [대체됨 → 2026-10-01 타일 큐 (머지 전 되돌림)]

- 결정: 로그인·가입 분할의 왼쪽 홈 칸에도 닫기를 둔다 (검색 분할과 같음, 사용자 요청). 닫으면 폼만 전체 폭, 폼 칸 닫기는 숨김. 이 전체 화면에서 로그인↔가입으로 이동하면 떠나온 칸을 위에 쌓지 않고 그 칸에서 바뀐다 (사용자 지시). 홈 칸이 열린 분할의 3칸 쌓기는 그대로.
- 저장: 닫힘은 세션 쿠키 `auth_home_closed`. (auth) 레이아웃은 URL 쿼리를 못 읽고 로그인↔가입 링크가 쿼리를 떨어뜨려 검색의 `home=0` 방식을 못 씀. 쿠키를 읽어 (auth) 화면은 요청마다 렌더.
- 재검토 조건: 닫은 홈 칸을 다시 여는 버튼이 필요해질 때, 좁은 화면(@lg 미만)의 위아래 쌓기도 없애기로 할 때.

## 2026-10-06 홈 실시간 목록은 가로 줄, 구매대행·경매 자리 비움 [대체됨 → 2026-10-13 실시간 목록·빈 자리 없앰]

- 결정: 실시간 구매요청·판매매물을 2칸 세로 목록(칸 높이에 맞는 행만) 대신 한 줄씩, 작은 카드가 옆으로 이어지는 가로 스크롤로 바꾼다. 모바일 탭도 없애고 같은 두 줄. 아이콘과 실시간 사이에 구매대행·경매가 들어올 자리를 점선으로 비워 둔다 (사용자 지시).
- 이유: 아래로 쌓으면 화면 높이에 따라 보이는 행 수가 들쭉날쭉하고, 넓은 화면에서 옆이 빈다. 가로 줄은 높이가 고정이라 "홈 스크롤 없이" 원칙을 지키면서 더 많이 보인다.
- 대안: 행 목록이 옆 칸으로 넘치는 다단 배치 — 사용자가 카드 줄을 골랐다.
- 재검토 조건: 구매대행·경매 기능이 정해질 때(자리 채우기), 실시간 목록이 실제 API로 바뀔 때.
