# 대량구매: 이름으로 매물을 바로 찾아 카드로 (2026-11-12)

> 사용자 지시("ㄱㄱㄱ", grilling 2026-11-12). 중간 규모 변경이라 이 파일 하나가 설계+계획. 브랜치 `feat/bulk-purchase-card-header`(PR #137)에 이어서.

## 설계

- **문제**: 구매자는 "상품마스터"를 모른다. 지금은 이름이 같은 마스터가 여럿이면 "상품을 고르세요" 후보 칩이 먼저 나오고 그다음에 매물이 나온다.
- **정리**: 매물에는 이름 칸이 없고 `prod_id` 로 마스터를 가리킨다(판매자가 등록할 때 쓴 상품명 = 마스터 이름). 그래서 "매물 제목으로 찾기"와 "마스터로 찾기"는 같은 일이다. 바꾸는 것은 **마스터를 사용자에게 고르게 하는 단계를 없애는 것**.
- **규칙**
  1. 줄의 이름(+적었으면 제조사·분류번호)이 대소문자·공백·하이픈 무시로 같은 마스터를 **모두** 찾아, 그 마스터들의 매물을 한 줄에 카드로 섞어 보인다(고정 순서: 단가 → 보증 → 상태 → 제공가능일 → 재고 → 등록일시). 마스터가 여럿이면 카드에 상품(이름·제조사·분류번호)이 붙는다.
  2. 이름이 같은 마스터가 없으면 이름이 **포함된** 마스터(최대 10개)의 매물을 같은 방식으로 보이고 줄에 "이름이 정확히 같은 상품이 없어 비슷한 상품의 매물을 보여 드려요" 안내를 붙인다.
  3. 둘 다 없으면 지금처럼 "상품마스터에 없는 상품이에요" + [상품 찾기].
  4. 상품ID 가 있으면(상품 찾기로 고른 줄) 그 마스터 하나.
- 미리 고르는 규칙("조건에 맞는 매물이 딱 하나일 때만")·조건·하드 막힘/조건과 다른 점·담기는 그대로. 고른 매물 검증은 합쳐진 매물 목록과 대조한다.
- **바뀌는 것**: 응답 `ListingOption` 에 상품(`prodId`·`prodName`·`prodBrand`·`prodClassNo`), 줄 결과에 `masterCount`. "같은 이름의 상품이 여럿이에요" 오류와 이름 겹침 후보 칩은 없앤다(마스터가 하나도 없을 때만 [상품 찾기]).
- **파일 안 중복**(같은 마스터가 두 줄이면 둘째 줄 실패)은 마스터가 **하나로 정해진 줄**에만 적용한다. 마스터가 여럿인 줄은 검사하지 않는다(이 규칙이 마스터 기준이라서). 대체품 제안도 마스터가 하나일 때만.
- 보관본 v4(옛 보관본은 `masterCount` 가 없어 카드가 안 보이므로 버린다).

## 영향

- 백엔드 `CartBulkService.checkOne`·`optionsOf`, DTO(`CartBulkRowResult`), `ProductService`(이름 포함 검색으로 Product 목록). 프론트 줄 카드(`hasMaster`·상품 표시·안내), 타입·보관·테스트. API 파라미터는 그대로라 Bruno 는 응답 설명만.
- 판매 쪽·장바구니·견적 변경 없음.
