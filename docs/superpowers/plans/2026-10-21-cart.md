# 장바구니 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 검색 결과·상세에서 매물을 장바구니에 담고, `/my/cart` 에서 골라 견적 요청·구매·빼기. 헤더 아이콘에 개수 배지.

**Architecture:** 장바구니 = `trd_trade_info` 행(TYPE `구매검토`, STATS `장바구니`). 새 `CartService`·`CartController`(`/api/v1/cart`)가 담기·목록·개수·빼기를 맡고, 기존 `TradeService` 의 견적·구매 성공 경로가 그 매물의 장바구니 행을 같은 트랜잭션에서 지운다. 프론트는 검색 결과 표(`ResultList`)를 `scope="cart"` 로 재사용하고, 칸(iframe)에서 헤더로 `cart-changed` postMessage 를 보내 배지를 갱신한다.

**Tech Stack:** Spring Boot 4.1 · Java 21 · JPA · Flyway · Testcontainers / Next.js 16 · Vitest · Playwright

**Spec:** `docs/superpowers/specs/2026-10-21-cart-design.md`

## Global Constraints

- 한 번에 담기 1~20개(`MAX_ADD = 20`), 장바구니 합계 100개(`MAX_ITEMS = 100`), 빼기 한 번에 1~100개. 프론트 `lib/validation/cart.ts` 와 서버 DTO 가 같은 값. security.md "입력 검증"이 원본.
- DB 값: TYPE `구매검토`(`TradeType.REVIEW`), STATS `장바구니`(`TradeStats.CART`). 이미 enum 에 있음.
- 새 오류 코드 `CART_FULL(HttpStatus.CONFLICT, "장바구니는 100개까지 담을 수 있습니다.")`. 프론트 `trade.errors.CART_FULL = "장바구니는 100개까지 담을 수 있어요. 안 쓰는 상품을 빼 주세요."`
- 장바구니 행은 판매자 목록·`pendingCounts`·내 구매목록(`role=buyer`)에 안 보인다. 메일 없음. 재고 안 건드림.
- 스키마 변경은 `db/trade-cart` 브랜치(마이그레이션만), 나머지는 `feat/cart`(`db/trade-cart` 위에서 시작, PR base 는 db PR 머지 뒤 main). git worktree 에서 작업.
- 사용자 문구는 `frontend/src/messages/` 에만. 주석·커밋·문서 한국어. 커밋 전 `./gradlew check`, `pnpm typecheck && pnpm lint && pnpm test`.

## Review Focus

1. 같은 매물을 두 칸에서 동시에 담기 → 둘 다 200, 행은 1개. (Task 2 `동시에_같은_매물_담기`)
2. 장바구니에서 [구매] 실패(재고 부족 409) → 장바구니 행이 남아야 함. (Task 3 `구매_실패하면_장바구니_남음`)
3. 담은 매물이 거래완료로 바뀜 → 목록에 남고 `tradeStatus:"completed"`, 프론트는 견적·구매 대상에서 뺌. (Task 2 `거래완료된_매물도_목록에_남음`, Task 6 `cartActionable` 테스트)
4. 남의 tradeId 를 섞어 빼기 → 404, 내 행도 안 지워짐. (Task 2 `남의_행이_섞이면_아무것도_안_지움`)
5. 장바구니 행 tradeId 로 기존 `/trades/{id}/cancel`·`/complete` 호출 → 행이 안 바뀜(409 `TRADE_NOT_PENDING`). (Task 3 `장바구니_행은_거래_동작에_안_걸림`)
