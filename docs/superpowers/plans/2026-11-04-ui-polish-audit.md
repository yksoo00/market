# 화면 점검 후 다듬기 (2026-11-04)

사용자가 화면을 점검시킨 뒤 고르고 지시한 항목 묶음. 새 테이블·API·권한 변경 없음 — 프론트만. 백엔드 정렬 값·API 는 그대로.

## 설계

| # | 항목 | 정한 방법 |
|---|---|---|
| 1 | 헤더 "임시 테이블" 768px 두 줄 꺾임 | 링크에 `whitespace-nowrap` |
| 2 | 담기 완료 모달이 뜰 때 상세가 칸을 벗어나 전체화면으로 커 보임 | 원인: `TileFrame` 이 모달 열림 중에는 `fixed inset-0` 이라 그때 잰 칸 위치가 창 전체. 담기 모달 → 완료 모달로 바로 이어질 때(부모가 아직 열림 상태) `modal-rect` 에 창 전체가 실려 iframe body 가 창 크기로 펴진다. 칸 위치를 재는 요소를 커졌다 줄었다 하는 안쪽이 아니라 늘 제자리인 바깥 칸으로 옮긴다 |
| 3 | 상세 정보 표가 한 쌍씩 아래로 길게 | 표 칸 자체를 컨테이너로 보고(`@container`), 그 폭이 30rem 이상이면 라벨·값 두 쌍을 한 줄에(지금은 칸 폭 80rem 이상일 때만). 값이 없는 행은 그대로 "–" (행을 숨기면 매물마다 표가 달라져 비교가 어렵다) |
| 4 | 상세 대표 사진이 깨졌을 때 alt 글자가 쏟아짐 | 장바구니 카드와 같은 `photoBroken` 상태 → 이미지 아이콘 자리 |
| 5 | 회원가입 "별명 사용" 줄이 좁게 꺾임 | 라벨은 한 줄 고정, 설명문은 그 아래 줄 |
| 6 | 검색창 placeholder 잘림 | 홈·검색·활동내역 입력창 문구를 짧게 (`모델명 · 제조사 · 부품명`; 예시는 "인기 검색"이 이미 보여 줌) |
| 7 | 장바구니 카드 "남은 시간 60분" 이 "60분"만 줄 바꿈 | 그 문구 한 덩어리를 `whitespace-nowrap` |
| 8 | 모바일 긴 상품명 | 카드·장바구니 이름 2줄까지 보이고 `…` (`line-clamp-2`). 전체 이름은 상세에서 (사용자 지시) |
| 9 | 표 열 정렬·폭 뒤죽박죽, 가로 스크롤이 너무 김 | 남들 규칙대로: 글자 왼쪽, 숫자(단가·수량·금액·최소주문·주문단위) 오른쪽, **머리글도 값과 같은 쪽**. 열 폭을 값 길이에 맞게 줄여 숫자 열이 옆 글자 열과 멀리 떨어지지 않게 하고, 표 `min-w` 도 줄인다. 열마다 값 최대 길이를 재서 정한다: 검색·내 판매(표 최소 폭 1288 → 1128), 거래이력(순서 변경). 활동내역은 폭이 자동이라 변경 없음 |
| 10 | 내 거래이력 열 순서 | 날짜 · 구분 · 상품 · **단가 · 수량 · 금액 · 상대** (상대를 맨 뒤로). 정렬 키·모바일 카드는 그대로 |

홈 아이콘 글자 없음(6번 점검 항목)은 사용자가 "일단 없어도 돼" — 하지 않음.

## 영향 검토
- 정렬 키·API·URL 쿼리는 안 바뀐다 (열 위치·폭·클래스만). `StickyXScroll`·`memoryKey` 그대로.
- `TileFrame` 은 모든 모달이 지나므로 e2e `modal.spec.ts`·`purchase.spec.ts` 로 확인. 새 화면 아님 → 타일 화면 표 변경 없음.
- 3분할 오른쪽 아래 칸(960×500)에서 모달·상세 표가 잘리지 않는지 확인.
