# 다량 등록·대량구매 양식 간소화: 사용자가 모르는 칸 빼기 (2026-11-24)

> **구현 방식:** CLAUDE.md "중간 크기 기능"대로 이 파일 승인 뒤 직접(native) 구현. 작업마다 리뷰하지 않고 PR 에서 `/code-review` 한 번. 단계는 `- [ ]` 로 추적.

**Goal:** 양식 내려받기의 칸에서 사용자가 알 수 없는 값(상품ID·분류번호·카테고리 코드)을 빼고, 판매자가 아는 칸만 남긴다. 옛 양식은 계속 읽는다.

**Architecture:** 파서가 필수 6칸만 헤더로 요구하고 나머지는 있으면 읽는다. 상품 찾기는 분류번호가 비면 그 칸을 보지 않는다. 새 상품의 카테고리는 엑셀 코드 대신 화면의 [카테고리 고르기]로 정한다 (이미 있는 기능).

**Tech Stack:** Spring Boot 4.1, POI(기존), Next.js. **새 라이브러리 없음, DB 스키마 변경 없음.**

## 설계

### 정해진 것 (사용자 지시 2026-11-24)

- 상품ID·분류번호·카테고리 코드는 사용자가 알 방법이 없다 → 양식에서 뺀다.
- 상품번호는 판매자가 제품에서 알 수 있다 → **남긴다**.

- 대량구매 양식도 같다 (사용자 지시 2026-11-24 "대량구매도 마찬가지야").

### 새 양식 칸 — 판매 다량 등록 (이 순서)

`상품명*` · `제조사*` · `상품번호` · `상품상태*` · `단가*` · `수량*` · `제공가능일*` · `최소주문수량` · `주문단위` · `설명` · `사진1`~`사진4` · `데이터시트`

### 내가 정한 가정 (승인 때 확인)

1. **헤더는 필수 6칸만 요구한다** (상품명·제조사·상품상태·단가·수량·제공가능일). 나머지는 있으면 읽고 없으면 빈 칸. 그래서 **옛 양식**(상품ID·분류번호·카테고리 코드 칸이 있는 것)도 그대로 읽힌다 — 이미 내려받아 쓰던 양식이 깨지지 않게. 새 양식에는 그 세 칸을 넣지 않는다.
2. **분류번호가 비면 상품 찾기에서 그 칸을 보지 않는다.** 지금은 비어 있으면 "분류번호도 비어 있는 마스터"만 같은 상품으로 본다(`findAllSameIgnoreCase`) — 분류번호가 있는 마스터는 이름·제조사가 같아도 못 찾고, 새 마스터를 또 만들게 된다. 바뀌는 규칙:
   - 분류번호가 **있으면**: 지금처럼 이름·제조사·분류번호 일치.
   - 분류번호가 **비면**: 이름·제조사(대소문자·공백 무시)가 같은 마스터가 **정확히 하나**일 때만 그 마스터. **둘 이상이면 자동으로 정하지 않고** 후보로 보여 사용자가 고르게 한다(2026-11-12 대량구매 상품 찾기와 같은 원칙). 없으면 새 마스터 후보.
3. **새 상품 줄의 카테고리**: 카테고리 코드 칸이 없으므로 새 마스터가 필요한 줄은 줄 오류 "카테고리를 골라 주세요"(`categoryCode`)로 시작하고, 화면의 [카테고리 고르기]로 고르면 풀린다. 코드를 아는 사람은 옛 양식 칸에 적어도 된다(그대로 읽는다).
4. 화면 입력칸(분류번호·카테고리·상품번호 등 SUB_FIELDS)은 **그대로 둔다** — 줄을 읽은 뒤 고칠 수 있어야 하고, 마스터를 고르면 채워진다.

### 새 양식 칸 — 대량구매 (`CartBulk`)

지금 양식: `상품명*` · `제조사` · `분류번호` · `상품ID` · `수량*` · `납품희망일*` · `요청사항` + 조건 8칸(최소상태·단가상한·최소보증(개월)·데이터시트·사진·불량지원·테스트리포트·정품인증서).

**칸별 "구매자가 아는 값인가" 검토** (칸마다 따져 본 결과)

| 칸 | 구매자가 아나 | 결정 |
|---|---|---|
| 상품명* | 안다 (사려는 물건 이름) | 남김 |
| 제조사 | 안다 | 남김 (선택) |
| 분류번호 | 모른다 (8자리 표준 코드) | **뺌** |
| 상품ID | 모른다 (시스템 내부 번호) | **뺌** |
| 수량*·납품희망일* | 안다 | 남김 |
| 요청사항 | 안다 (자유 글) | 남김 |
| 최소상태 | 안다 — 드롭다운에서 고름 | 남김 |
| 단가상한 | 안다 (예산) | 남김 |
| 최소보증(개월) | 안다 — 드롭다운 | 남김 |
| 데이터시트·사진·불량지원·테스트리포트·정품인증서 | 안다 — "이게 있는 매물만" 이라는 구매자 자신의 조건, 드롭다운 Y | 남김 |
| (화면에서만) 판매자ID·등록일시 | 모른다 — 양식에는 원래 없고 화면에서 매물 카드를 눌러 정해짐 | 그대로 |

- **양식에서 뺄 칸: 분류번호, 상품ID** 둘뿐. 나머지는 구매자가 직접 정하는 값이라 남긴다.
- **화면 줄의 입력칸에서도 분류번호를 뺀다.** 지금 줄마다 "분류번호" 입력칸이 있는데(`BUY_INPUT_FIELDS`) 구매자는 적을 수 없다. 단 마스터를 고르면 그 마스터의 분류번호가 줄에 **내부 값으로** 채워져 같은 이름 마스터를 정확히 가리는 데 쓰인다(`lib/buyBulk.ts` pick 동작 유지). 카드의 상품 라벨 "이름 · 제조사 · 분류번호"는 같은 이름 마스터를 구분해 주므로 값이 있을 때만 그대로 보인다.
- 헤더 필수는 **상품명·수량·납품희망일 3칸**만. 제조사·요청사항·분류번호·상품ID·조건 칸은 있으면 읽는다 → 옛 양식도 그대로 읽힌다.
- 상품 찾기는 **이미 분류번호가 비면 그 칸을 보지 않는다**(`ProductService.findAllLoose`) — 매칭 규칙은 안 바꾼다. 이름이 같은 마스터가 여럿이어도 고르게 하지 않고 매물을 합쳐 보이는 기존 동작 그대로.
- **상품번호는 대량구매에 넣지 않는다**: 대량구매의 상품 찾기는 상품번호를 쓰지 않아 넣어도 효과가 없다 (요청 밖 칸을 늘리지 않음).
- 증빙 5칸의 헤더 이름("사진" 등)은 그대로 둔다 — 이름을 바꾸면 이미 받은 양식이 안 읽힌다. 뜻은 화면 라벨(`messages/buyBulk.ts`)과 드롭다운(Y)이 알려 준다.
- 양식 파일 `CartBulkTemplate`·조건 칸 열 번호와 드롭다운 위치 갱신.

### API·화면 변경

- API 모양 변경 없음. `BulkRowDto` 그대로(칸이 비어 올 뿐).
- 서버 문구: `"마스터에 없는 상품이라 카테고리 코드가 필요합니다."` → `"마스터에 없는 상품이에요. 카테고리를 골라 주세요."` (프론트가 이 문구를 `categoryCode` 칸 오류로 그대로 보인다.)
- `messages/listing.ts`: 드롭존 안내(`hint`)·`zipHint` 중 양식 칸 설명이 있으면 새 칸에 맞춤. 새 상품 안내 문구(`newMasterHint`)에 "카테고리를 골라 주세요" 추가.
- 양식 파일: `ListingBulkTemplate` 칸·상품상태 드롭다운 열 번호(`PROD_STATE_COLUMN`) 갱신.

### 영향 검토

- 대량구매는 **양식과 헤더 검사만** 바꾼다 (상품 찾기·담기 규칙·장바구니 100줄 규칙은 그대로). 견적 대량·단건 등록은 **안 건드린다**.
- `ProductService.findSameIgnoreCase` 는 다량 등록만 쓴다(확인 필요 — 작업 1에서 `grep`). 쓰는 곳이 더 있으면 새 메서드로 분리한다.
- 마스터에 분류번호가 없는 상품(개발 DB 샘플 대부분)은 지금과 결과가 같다. 분류번호가 있는 마스터는 이제 찾아진다(고치는 쪽).
- 같은 이름·제조사 마스터가 여럿인 상품은 자동 선택이 사라진다 → 후보 고르기 화면(이미 있음)을 거친다.
- 같은 파일 안 중복 검사(`seen` 키)는 그대로: 해석된 마스터 id, 새 마스터는 이름·제조사·분류번호.
