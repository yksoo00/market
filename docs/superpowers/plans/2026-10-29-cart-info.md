# PR 3 trd_cart_info (장바구니·비교) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 장바구니·비교를 정의서 `TRD_CART_INFO` 로 옮긴다 — 담을 때 수량·납품희망일·요청사항을 받고, 비교는 검색 목록에서 `비교용` 행으로 저장하며, 검색 목록에 체크한 매물이 계속 보이는 "선택한 상품" 줄을 둔다.

**Architecture:** 담기 1건 = `trd_trade_info` 1행(`구매검토`, 거래상태 `장바구니`|`비교용`) + `trd_cart_info` 1행(같은 거래ID). 목록·개수·배지는 `trd_cart_info` 에서 읽고 매물 값은 지금 값(검색 결과와 같은 칸). 장바구니 → 구매·견적은 `trd_cart_info` 행을 지우고 **같은** `trd_trade_info` 행을 바꾼다. 비교 화면은 주소가 아니라 내 `비교용` 행을 읽는다.

**Tech Stack:** Spring Boot 4.1, JPA(`@IdClass`, `Persistable`), Flyway, PostgreSQL 16, Testcontainers / Next.js 16, zod, react-hook-form, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-27-definition-realign-design.md` "PR 3" 절 + "검색 목록의 선택 줄". 정의서 `KPIT-BRK-테이블정의서.xlsx` CART_INFO·TRADE_INFO 시트(10/27 14:08 판, 10/29 다시 확인 — 바뀐 것 없음).

## Global Constraints

- 브랜치 `db/cart-info`, worktree `C:\market-cart`. PR #88(상품마스터)이 머지된 main 에서 시작한다 — 비교의 소분류 판정이 `trd_prod_master.minor_category` 를 쓴다. 아직 머지 전이면 `db/product-master` 위에 쌓고, 머지되면 rebase.
- 테이블은 정의서 + 설계서 PR 3 표대로. 정의서 밖 제약·인덱스는 더하지 않는다 — 단 `ux_trd_trade_info_one_cart` 는 이미 있는 인덱스를 거래상태까지 포함하게 바꾸는 것(판정 1).
- `trd_cart_info` PK `(user_id, trade_id, ser_no)`. FK 없음. 정의서 NOT NULL 그대로: `prod_date`·`prod_name`·`prod_no`·`prod_spec_info`·`prod_state`·`prov_date`·`order_unit_price`·`order_quantity`·`req_deli_date`·`reg_date`. 빈 사양은 `''`.
- `cart_type` 값은 `장바구니` / `비교용` (정의서 설명 "방바구니/비교용바구니" 는 오타 — 설계서 `cart_type=비교용`).
- 같은 매물은 장바구니·비교에 **각각 1줄**. 이미 담긴 매물을 다시 담으면 건너뛰고 처음 값 유지, 응답으로 알린다 (설계서 가정 2 확정).
- 담기 입력은 구매와 같은 검증: 주문량 ≥ 최소주문량·주문단위 배수·금액 int 이하, 납품희망일 필수·실제 날짜·오늘(한국) 이후, 요청사항 ≤100자. 재고는 보지 않는다(지금도 "재고가 모자라도 담아 둔다", `cartBlocked`). 비교는 입력 없음: 수량 = 최소주문량(없으면 1), 납품희망일 = 제공가능일, 요청사항 없음.
- 한도: 장바구니 한 번에 20개·합계 100개(지금 그대로). 비교 합계 4개·같은 소분류.
- 내 매물은 담기·비교 모두 `TRADE_OWN_LISTING`. 거래완료 매물은 장바구니 담기 `LISTING_COMPLETED`, 비교는 허용(보기만, 지금과 같음).
- `구매검토` 행은 내 활동내역·판매자 화면·요청 건수·검색 범위 판정에 나오지 않는다 (지금 `tradeType <> 구매검토` 조건 유지).
- 사용자에게 보이는 문구는 `frontend/src/messages/`. 입력 수치는 `docs/security.md` "입력 검증"이 원본, 프론트·백엔드 같은 값.
- UTF-8, 한글 파일은 국소 수정. 공개 저장소 — 실제 주소 쓰지 않는다.
- 새 화면·모달 체크리스트(`.claude/rules/frontend.md`): 화면 표 등록, `useTileOpen()`, 3분할 오른쪽 아래 칸(960×500, 640×330)에서 모달이 안 잘리는지. 이번에 새 `page.tsx` 는 없다(`/my/cart/compare` 유지).

## 판정 (설계서가 직접 말하지 않아 이 계획이 정한 것 — 틀리면 고친다)

1. **`ux_trd_trade_info_one_cart` 를 `trade_stats` 포함으로 바꾼다**: 지금은 `(user_id, seller_id, prod_reg_date, prod_id) where 구매검토/장바구니`. 비교에도 "매물당 1줄"이 필요해 `where trade_type='구매검토'` 로 넓히고 컬럼에 `trade_stats` 를 더한다(이름 `ux_one_cart` 유지, drop + create). 새 인덱스가 아니라 기존 인덱스 변경.
2. **비교는 "비교 바구니" 하나**: [비교] = 선택한 매물을 내 비교 바구니에 담는다(이미 있는 건 건너뜀). 담은 뒤 바구니 전체가 같은 소분류·4개 이하여야 한다 — 아니면 담기 전체 거부 + 문구. 비교 화면은 바구니 전체를 보인다. 예전 비교 세트가 남아 다른 소분류를 못 담는 경우를 위해 비교 화면에 열마다 [빼기] 와 [모두 비우기].
3. **비교 화면은 1개만 남아도 열을 보인다**(빼기·비우기를 할 수 있게). 2개 미만이면 위에 "2개 이상 담아야 비교할 수 있어요" 안내만 더한다 — 지금은 안내만 있고 열이 없어 마지막 하나를 못 뺀다.
4. **구매·견적은 `장바구니` 행만 변환**한다. 비교 행은 그대로 둔다(비교는 계속 볼 수 있게). 이미 같은 매물의 견적 행이 있으면(구매자·매물당 견적 1행, `ux_one_quote`) 장바구니 행을 견적으로 바꾸지 않고, 지금처럼 그 견적 행을 덮어쓰고 장바구니 행(두 테이블)만 지운다.
5. **담은 입력값은 구매·견적 모달의 기본값**으로 쓴다(장바구니 화면에서 [구매]·[견적 요청] 누르면 담을 때 수량·납품희망일·요청사항이 채워져 열림). 모달에서 바꿀 수 있다.
6. **장바구니 담기 모달**: 선택한 매물 1~20개를 한 모달에서, 매물마다 수량·납품희망일(기본 제공가능일)·요청사항 한 줄(견적 모달과 같은 모양, 단가 칸 없음). 매물 하나인 상세 화면도 같은 모달.
7. **`trd_cart_info.ser_no`** = 그 구매자 행 중 최대 + 1. 동시에 두 요청이 같은 값을 받을 수 있으나 PK 에 `trade_id` 가 있어 충돌하지 않는다(감수).
8. **API 모양**: `POST /api/v1/cart`(담기, 본문에 수량 등), `GET /api/v1/cart`, `POST /api/v1/cart/remove` 유지; 비교는 `POST /api/v1/cart/compare`(담기), `GET /api/v1/cart/compare`, `POST /api/v1/cart/compare/remove`(tradeIds), `POST /api/v1/cart/compare/clear`. 화면 `/my/cart/compare` 는 `items` 주소 값을 없앤다.

## Review Focus

1. 같은 매물을 다시 담으면 처음 값 유지·행 늘지 않음, 동시에 두 요청이어도 1행 — Task 2 `addTwiceKeepsFirstValues`, `concurrentAddMakesOneRow`.
2. 담기 중 한 매물이 틀리면(내 매물·거래완료·최소주문량 미달·지난 납품희망일) 아무것도 안 담김 — Task 2 `oneInvalidItemAddsNothing`.
3. 비교 합계 5개·다른 소분류는 거부하고 아무것도 안 담김, 기존 바구니와 합쳐서 판정 — Task 3 `compareUnionRules`.
4. 장바구니 행이 구매·견적으로 바뀐 뒤 `trd_cart_info` 행은 없고 같은 거래ID 의 `trd_trade_info` 행이 구매요청/견적요청 — 구매가 재고 부족으로 실패하면 장바구니 두 행 그대로 — Task 4.
5. 매물 삭제·상품 변경이 `trd_cart_info` 를 같이 처리(고아 행·찾지 못하는 prod_no 없음) — Task 4 `listingDeleteRemovesCartInfo`, `productChangeFollowsCartInfo`.
