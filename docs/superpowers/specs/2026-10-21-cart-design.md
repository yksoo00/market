# 장바구니: 담아 두고 나중에 견적 요청·구매

> 2026-10-21. 사용자 지시(대화)로 정함. 비교용(`구매검토`/`비교용`)은 다음 작업.

## 목적

구매자가 검색 결과·상세에서 매물을 장바구니에 담아 두었다가, 장바구니 화면에서 골라 [견적 요청]·[구매]로 넘긴다.
장바구니는 기록으로 남길 필요가 없다 (사용자) — 빼거나 견적·구매로 넘어가면 행을 지운다.

## 결정 (사용자)

- 장바구니는 **따로 된 페이지** `/my/cart` + **헤더 장바구니 아이콘(개수 배지)**. 10/21 "장바구니·비교용은 내 구매 안의 상태" 계획을 바꾼다 → decisions.md.
- 담기는 **클릭 한 번** (모달 없음). 수량·단가는 나중에 견적·구매 모달에서 지금처럼 입력.
- [빼기]는 **바로 행 삭제**. Redis 에 두었다가 1시간 뒤 지우는 안은 뺐다 — 만료 시점에 확실한 신호가 없어 스케줄러가 따로 필요하고, 그동안 DB·Redis 두 곳을 같이 봐야 해서. 되돌리기 알림도 이번엔 없음.
- 장바구니에서 [구매] → 기존 구매요청, [견적 요청] → 기존 견적요청. 그 매물의 장바구니 행은 지운다.
- 아래 세 가지는 Claude 가 제안했고 사용자가 "일단 해봐"로 진행시킴 (spec 검토 때 바꿀 수 있음): 부분 unique 인덱스, 한도 100개, 검색에서 바로 견적·구매해도 장바구니에서 빠짐.

## 데이터 (`trd_trade_info`)

- 매물 1개 = 1행. TYPE `구매검토`, STATS `장바구니`. 행은 만든 뒤 TYPE 이 바뀌지 않는다(10/20 규칙) — 견적·구매로 넘어갈 때 장바구니 행을 지우고 기존 흐름이 새 행(또는 기존 견적 행 덮어쓰기)을 만든다.
- 스냅샷 칸(prod_id·단가·재고 등)은 다른 행처럼 담을 때 복사. NOT NULL 칸: `order_unit_price` = 담을 때 등록단가, `order_quantity` = 최소주문량(없으면 1). `req_deli_date`·`remarks` null. 화면은 이 값이 아니라 **지금 매물 값**을 보여 준다.
- 구매자·매물당 장바구니 행 하나: 부분 unique 인덱스 `ux_trd_trade_info_one_cart (user_id, seller_id, reg_date) where trade_stats = '장바구니'` — **정의서 밖 인덱스**. 마이그레이션 `V202610211300__trade_one_cart_per_listing.sql`, `db/trade-cart` 브랜치로 따로. 직전 배포 코드와 호환(인덱스만 추가, 장바구니 행은 아직 없음).

## 흐름

| 동작 | 조건 | DB | 재고 | 메일 |
|---|---|---|---|---|
| 담기 | 로그인, 남의 매물, 거래완료 아님, 한 번에 1~20개, 담은 뒤 합계 100개 이하 | 행 생성. 이미 담긴 매물은 건너뜀(성공) | 그대로 | 없음 |
| 빼기 | 내 장바구니 행 | 행 삭제. 남의 행·없는 행은 무시하지 않고 404 | 그대로 | 없음 |
| 견적 요청 | 기존 견적 규칙 | 기존대로 + 그 매물들의 내 장바구니 행 삭제 (같은 트랜잭션) | 그대로 | 판매자 (기존) |
| 구매 | 기존 구매 규칙 | 기존대로 + 그 매물의 내 장바구니 행 삭제 (같은 트랜잭션) | 줄임 (기존) | 판매자 (기존) |
| 매물 삭제 | 판매자 | 그 매물의 장바구니 행도 삭제 (`TradeListingCleanup`) | — | 없음 |
| 매물 거래완료 | — | 장바구니 행은 남김. 화면에 거래완료 표시 | — | 없음 |

- 견적·구매 때 장바구니 삭제는 **어디서 눌렀든** 한다(장바구니·검색·상세). 그래서 견적·구매 API 는 바뀌지 않는다.
- 견적·구매가 실패(400·409)하면 트랜잭션이 롤백돼 장바구니 행도 남는다.
- 장바구니 행은 판매자 쪽 어디에도 안 보인다: `findSellerPage`·`countBySellerGroupByListing` 에서 제외. 내 구매목록(`findBuyerPage`)에서도 제외 — 장바구니 페이지에서만 본다.
- 동시에 같은 매물을 담아 unique 인덱스에 걸리면 성공으로 본다(이미 담김).

## API (`/api/v1/cart`, 로그인 필수, 내 행만)

| 요청 | 본문/응답 | 오류 |
|---|---|---|
| `POST /cart` | `{items:[{sellerId, regDate}]}` (1~20) → `{count}` (담은 뒤 합계) | 400 개수·형식, 403 `TRADE_OWN_LISTING`, 404 `LISTING_NOT_FOUND`, 409 `LISTING_COMPLETED`, 409 `CART_FULL`(100 초과) — 하나라도 틀리면 아무것도 안 담음 |
| `GET /cart` | `{items:[CartItem]}` 최신순, 페이지 없음(최대 100) | — |
| `GET /cart/count` | `{count}` | — |
| `POST /cart/remove` | `{tradeIds:[...]}` (1~100) → 204 | 404 `TRADE_NOT_FOUND`(내 장바구니 행이 아님) — 하나라도 틀리면 아무것도 안 지움 |

- `CartItem` = 검색 결과 항목(`ListingSearchItem`)과 같은 칸(지금 매물 값) + `tradeId`. 프론트가 검색 결과 표를 그대로 쓰려고.
- 빼기를 `DELETE` + 본문으로 하지 않은 이유: 프록시가 DELETE 본문을 버릴 수 있다.
- Bruno 요청 파일 4개 추가. 수치는 security.md "입력 검증"에 추가(프론트 `lib/validation/cart.ts` 와 같은 값).

## 프론트

**헤더 장바구니 아이콘**: 로그인 때만, 앱 메뉴(∷) 왼쪽, 모바일도. 1 이상일 때 배지, 99 초과는 `99+`. 누르면 `/my/cart` 를 새 주기능 칸으로(헤더에서 여는 다른 화면과 같은 규칙).
숫자는 로그인 확인 뒤 `GET /cart/count`, 그리고 `cart-changed` 신호를 받을 때 다시 조회. 칸은 iframe 이라 담기·빼기·견적·구매 성공 뒤 `window.top.postMessage({source:"market-tile", type:"cart-changed"}, origin)` (최상위 창이면 자기 자신에게) — 칸 열기 신호와 같은 통로.

**담기 버튼**: 검색 결과(체크한 것, 20개까지) · 매물 상세에 [장바구니]. 성공하면 `ResultDialog` "장바구니에 담았어요" + [장바구니 보기]. 로그인 안 함·내 매물은 기존 [구매]의 `block` 처리. 내 판매글(`scope="mine"`)엔 없음.

**`/my/cart`**: `tileScreens` 에 `{ id: "myCart", group: "buy" }`. 검색 결과 부품 `ResultList` 를 `scope="cart"` 로 재사용. 체크 후 [견적 요청](여러 개, `QuoteDialog`) · [구매](1개, `PurchaseDialog`) · [빼기](여러 개, 확인 없이). 성공하면 목록을 다시 불러온다. 거래완료 매물은 배지 + 견적·구매 대상에서 빠지고 [빼기]만. 빈 화면 "장바구니가 비었어요" + [상품 검색]. 문구는 `messages/cart.ts`.

## 오류 처리

- 담기·빼기 실패는 `ResultList` 의 기존 알림(`showNotice`)에 서버 문구(`messages/trade.ts` 의 오류 코드 매핑에 `CART_FULL` 추가).
- 장바구니 목록·개수 조회 실패: 목록은 기존 검색 결과의 오류 화면, 배지는 숨김(헤더를 막지 않는다).
- 장바구니에서 연 견적·구매 모달의 오류는 지금 모달 처리 그대로.

## 감수

- 거래ID(`yyMMddHH` + 순번 3자리)는 한 시간에 999개. 장바구니 행도 ID 를 쓰므로 많이 담으면 `TRADE_ID_EXHAUSTED` 가 빨리 온다. 지금 사용자 수로는 문제없음 — 재검토: 시간당 거래·장바구니가 수백 건이 될 때.
- 담은 사람이 판매자에게 안 보이므로 "관심 있는 사람 수" 같은 건 없다.

## 범위 밖

비교용, 장바구니 수량 저장·수정, 되돌리기 알림, 장바구니 단가 변동 알림, 마이페이지·사용자 메뉴 링크(헤더 아이콘으로 충분).
