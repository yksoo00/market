# 상품 등록: 상품마스터에서 고르기, 없으면 직접 입력

> 2026-10-14. 사용자 지시(대화): 등록할 때 상품마스터에서 상품을 고르면 정보가 채워져 저장되고,
> 마스터에 없으면 직접 입력해서 그 입력이 상품마스터에 저장된다. 판매자가 데이터시트·사진을 안 올렸을 때만 마스터의 것을 쓴다.
> 카테고리는 검색 목록에서 고른다. 어드민의 마스터 수정은 나중(어드민 계정을 만들 때 역할과 함께).

## 목적

임시로 둔 카테고리 코드 직접 입력·상품 정보 직접 입력을 없애고, 상품마스터(50건 시드, 계속 늘어남)를 중심으로 등록한다.

## 사용자 결정 (대화 2026-10-14)

- 마스터에 있으면 고른다. 없으면 직접 입력하고, 그 입력이 마스터에 저장된다 (지금의 `findOrCreate` 유지).
- 카테고리는 소분류 검색 목록 한 개 ("기업용 컴퓨터 > 데스크톱 > 사무용 PC"처럼 전체 경로 표시, 이름을 치면 걸러짐). 코드는 자동 입력.
- 데이터시트·사진은 판매자가 올리지 않았을 때만 마스터 것을 쓴다.
- 어드민 마스터 수정은 이번 범위 밖.

## 정한 것 (사용자가 안 정해서 내가 고름 — 틀리면 알려 달라)

- 마스터를 고르면 상품 칸(카테고리·상품명·제조사·상품번호·제조일·사양)은 채워진 채 잠긴다(읽기 전용). [직접 입력으로 바꾸기]를 누르면 비워지고 풀린다.
- 마스터 데이터시트·사진은 **등록 시점에 매물 칸으로 복사**한다(키 문자열만). 나중에 마스터가 바뀌어도 이미 등록된 매물은 그대로(스냅샷). 이유: 상세·검색·수정이 읽는 `trd_prod_reg` 칸을 그대로 쓰므로 읽기 쪽 코드를 안 바꾼다.
- 마스터를 안 고르고(직접 입력) 새 마스터가 만들어질 때, 그 상품의 데이터시트·대표 사진은 이 판매자가 올린 것으로 채운다 (대표 사진은 지금도 그렇다. 데이터시트가 새로 추가). 이름+제조사가 이미 있으면 기존 마스터를 그대로 쓰고 입력값은 무시한다 (지금 동작).
- 직접 입력일 때 대표 사진은 지금처럼 필수. 마스터를 골랐고 그 마스터에 사진이 있으면 사진 없이도 등록된다(마스터 사진이 대표). 마스터에도 사진이 없으면 필수.
- 마스터 검색: 상품명·제조사·상품번호(MPN)에 대한 부분 일치(대소문자 무시), 최대 10건. 로그인한 사용자만.
- 카테고리 목록: `is_display='Y'` 전부(239건)를 한 번에 준다. 소분류만 선택 대상. 경로 이름은 코드 앞부분(`E01`, `E01-F01`)으로 부모를 찾아 프론트가 만든다.

## API

### GET /api/v1/products?q=…  (로그인 필요)
- `q` 공백 제거 후 1~50자. 이름·제조사·MPN 중 하나에 포함, 최대 10건, 이름순. `%`·`_`는 문자 그대로 검색(이스케이프).
- 응답 항목: `prodId`, `categoryCode`, `categoryName`, `prodName`, `prodNo`(=prod_mpn), `prodBrand`, `prodMufcDate`, `prodSpecInfo`, `prodDataSheet`, `prodPhoto1`.
- 개인정보 없음. 등록 한도(시간당 10회)와 별개로 읽기라 한도를 두지 않는다 (`/listings/mine`과 같은 방침).

### GET /api/v1/categories  (로그인 필요)
- `is_display='Y'`를 코드순으로. 항목: `categoryCode`, `categoryName`, `categoryDepth`, `categoryClass`, `parentCode`.

### POST /api/v1/listings (변경)
- 새 선택 필드 `prodId` (`@Size(max=20)`). 있으면 서버가 마스터를 읽어 상품 칸을 채운다. 요청의 상품 칸(`categoryCode`·`prodName`·`prodBrand`·`prodNo`·`prodMufcDate`·`prodSpecInfo`)은 **무시**한다 (클라이언트 값 불신).
  - 없는 `prodId` → 400 `fields.prodId` "없는 상품입니다."
- `prodId`가 없으면 `categoryCode`·`prodName`·`prodBrand` 필수 → 서비스에서 검사해 400 `fields.<이름>` "필수 입력입니다."(Bean Validation의 `@NotBlank`는 조건부라 떼고 `@Size`만 남긴다). 카테고리 존재 검사는 지금과 같다.
- `photos` `@NotEmpty` 해제 → 서비스에서: 비어 있고(마스터를 골랐고 그 사진이 있는 경우 제외) → 400 `fields.photos` "대표 사진을 올려 주세요."
- 데이터시트: `listingDataSheet`가 없고 마스터에 있으면 마스터 키를 복사. 사진: `photos`가 비어 있고 마스터에 사진이 있으면 `prod_photo_1`에 마스터 키를 복사(2~4번째 칸은 비움). 복사한 키는 업로드 기록(claim) 대상이 아니다 (이미 저장된 파일이므로).
- 기존 `productDataSheet`는 그대로 두되 새 마스터를 만들 때 `productDataSheet`가 없으면 `listingDataSheet`를 마스터 데이터시트로 쓴다.

## 화면 (`/listings/new`, ListingForm) — 2026-10-14 사용자 지시로 정정

- 상품 정보 섹션 맨 위 "상품 찾기" 드롭다운(카테고리 칸과 같은 콤보박스). **처음엔 아무것도 고르지 않은 상태이고 아래 상품 칸(카테고리·제조사·상품명·번호·제조일·사양)은 전부 잠겨 있다.**
- 누르면 맨 위 "직접 입력" + 마스터 목록(이름순 앞 10건, 이름·제조사·번호를 치면 300ms 뒤 걸러짐, 빈 검색어도 허용). 목록에 없으면 "직접 입력".
- 마스터를 고르면 상품 칸이 마스터 값으로 채워진 채 잠긴다. "직접 입력"을 고르면 상품 칸이 비워지고 열린다(카테고리 검색 목록도 이때만 열림). 마스터에서 직접 입력으로 바꿀 땐 마스터 값을 비우고, 이미 직접 입력 중이면 쳐 둔 값을 지우지 않는다.
- 데이터시트·사진 업로더는 그대로. 마스터에 있으면 "올리지 않으면 상품마스터의 파일을 써요" 안내, 마스터 사진이 있으면 대표 사진 필수 표시를 푼다.
- 제출: 마스터면 `prodId`+매물 칸만, 직접 입력이면 상품 칸까지. 상품 칸이 비어 있으면(아무것도 안 고름) 필수 검증에 걸려 [등록]이 꺼져 있다.
- 새 문구는 `messages/listing.ts`에.

## 감수

- 마스터 데이터시트·사진을 복사한 매물은, 나중에 어드민이 마스터를 고쳐도 따라가지 않는다. 같이 바뀌어야 하면 읽을 때 마스터를 조회하는 방식으로 바꿔야 한다.
- 샘플 마스터의 파일명은 업로드 키 형식이 아니라, 그 사진을 복사한 매물을 수정할 때 사진 키 검사에서 걸릴 수 있다. 실제 파일이 올라간 마스터에서는 문제 없다.
