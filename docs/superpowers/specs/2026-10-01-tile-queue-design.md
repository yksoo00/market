# 타일 큐 설계 (모든 화면 전환을 하나의 큐로)

> 2026-10-01. 9/29 타일 워크스페이스(`2026-09-29-tile-workspace-design.md`)를 고친다. 결정 기록: decisions.md "2026-10-01 화면 전환은 전부 타일 큐 엔진".

## 목적

화면 전환을 특정 화면마다 처리하지 않고 엔진 하나가 맡는다. 연관된 화면은 큐로 옆에 쌓고(전체 → 1/2 | 1/2 → 1/2 | 1/4·1/4), 가득 차면 가장 오래된 칸이 빠진다. 연관 없는 화면을 열면 리셋. 새 화면을 만들 때는 화면 표에 한 줄만 추가한다.

## 용어

- **칸(pane)**: 화면 하나. 칸 목록 `panes`는 오래된 순. `panes[0]`이 왼쪽(주소창) 칸.
- **화면(screen)**: 같은 화면 안의 이동인지 판단하는 단위. 경로 묶음 (예: `/signup/**` 전체가 "가입" 화면).
- **그룹(group)**: 연관 판단 단위. `common`은 어느 그룹과도 연관.

## 화면 표 (`lib/tileScreens.ts`, 이 파일만 고쳐서 화면 추가)

| 화면 | 경로 | 그룹 |
|---|---|---|
| home | `/` | common |
| login | `/login`, `/login/**` | common |
| signup | `/signup`, `/signup/**` | common |
| listingDetail | `/listings/{userId}/{regDate}` | common |
| search | `/search` | buy |
| buyRequest | `/requests`, `/requests/**` | buy |
| buyQuotes | `/quotes` (단 `/quotes/adjust` 제외) | buy |
| sellNew | `/listings/new` | sell |
| sellExtra | `/listings/extra` | sell |
| sellQuote | `/quotes/adjust` | sell |

- 판매·구매·공통은 첫 내용일 뿐이고 규칙은 모든 화면에 같다.
- 표에 없는 경로는 **그 경로 자체가 하나의 화면, 그룹 없음** → 다른 화면을 열면 항상 리셋.
- 더 구체적인 경로가 먼저 맞는다 (`/listings/new`가 `/listings/{userId}/{regDate}`보다 먼저, `/quotes/adjust`가 `/quotes`보다 먼저).

## 열기 규칙 (`decideOpen`)

현재 칸 목록과 클릭한 칸(어느 칸에서 눌렀는지), 열 경로를 받아 다음 중 하나:

1. **제자리**: 연 경로가 클릭한 칸과 **같은 화면** → 그 칸 안에서 이동. 칸 수 그대로. 예: 가입 1단계 → 2단계, `/search?q=a` → `?q=b`.
2. **리셋**: 연 경로의 그룹이 열린 칸들과 **연관 없음** → 그 경로 하나만 전체화면. 연관 = 새 화면 그룹이 `common`이거나, 열린 칸 중 `common`이 아닌 칸들의 그룹이 모두 새 그룹과 같음. 그룹 없는 화면은 자기 화면 외엔 연관 없음.
3. **큐에 추가**: 그 외. 새 칸을 맨 뒤에 붙인다. 이미 3칸이면 `panes[0]`(가장 오래된 칸)을 빼고 나머지를 당긴다 → 새 `panes[0]`이 주소창 칸이 된다.
4. 이미 같은 화면의 칸이 열려 있으면(클릭한 칸이 아닌 다른 칸) 그 칸을 새 경로로 바꾼다 (같은 화면이 두 칸에 생기지 않게).

**로고**는 항상 리셋 (`/` 전체화면). 링크에 `data-tile="reset"`을 붙여 표시.

## 배치

- 1칸: 전체. 2칸: `panes[0]` | `panes[1]` 1:1. 3칸: `panes[0]` 왼쪽 1/2, 오른쪽 위 `panes[1]` 1/4, 오른쪽 아래 `panes[2]` 1/4 (읽는 순서 = 오래된 순서, 새 칸은 오른쪽 아래 — 사용자 확인).
  - 9/29 스펙은 "새 칸이 오른쪽 위"였다. 진짜 큐에서 칸이 빠질 때 모든 칸이 읽는 순서로 한 칸씩 당겨지도록 새 칸을 오른쪽 아래로 바꾼다.
- `panes[0]`은 Next.js 라우터가 그리는 실제 페이지(주소창 = 이 칸 경로). 나머지는 `<iframe>` (9/29 결정 그대로).
- 화면 폭 768(`md`, 모바일) 미만이면 분할하지 않는다 (사용자 지시: 모바일 정도에서만): 열기 규칙의 "큐에 추가"도 제자리 이동처럼 주소창 칸만 바꾼다. 768 이상(태블릿·데스크톱)은 분할. 이미 분할된 상태에서 창을 768 미만으로 줄이면 주소창 칸만 보이고 나머지 칸은 숨긴다(목록은 유지해 다시 넓히면 보임).

## 닫기

- 칸이 2개 이상이면 **모든 칸** 오른쪽 위에 닫기(×). 1칸(전체)이면 닫기 없음.
- iframe 칸 닫기: 목록에서 빼고 당긴다.
- `panes[0]` 닫기: 목록에서 빼고, 새 `panes[0]`의 경로로 `router.replace` (기록을 쌓지 않아 뒤로가기가 닫기 전 상태를 거치지 않음).

## 전환을 엔진이 받는 방법 (화면 코드는 일반 `<Link>`·`<form>` 그대로)

- 엔진이 문서 전체의 클릭을 캡처 단계에서 듣는다: 같은 출처 `<a>`, 왼쪽 클릭, 수정키 없음, `target` 없음, `download` 없음일 때만 가로채고 `decideOpen`. 그 외는 브라우저 기본 동작.
- GET `<form>` 제출도 같은 방식으로 받는다 (홈 검색창 → `/search?...`). POST 폼·`action`이 함수인 폼은 건드리지 않는다.
- `router.push`로 하는 이동(필터 '적용' 등)은 그 칸 안의 이동이라 엔진이 관여하지 않는다 — 대신 아래 "주소창 칸 경로 동기화"로 칸 경로를 맞춘다.
- iframe 칸 안의 클릭·제출: iframe 안의 엔진이 가로채 부모에 `postMessage({ source: "market-tile", type: "open", path, paneKey })`. 부모가 `decideOpen` 후 결과를 적용. 제자리 이동이면 부모가 그 iframe에 이동하라고 돌려보내지 않고, iframe이 스스로 이동한다(제자리 판단은 iframe 쪽에서도 같은 표로 먼저 한다).
- iframe은 지금처럼 자기 현재 경로를 부모에 보고 (`useReportTilePathname`) → 칸 경로 갱신.

## 주소창 칸 경로 동기화

- 주소창 경로가 바뀌면(링크 외 이동, 뒤로가기 포함): 새 경로가 `panes[0]`과 같은 화면이면 `panes[0].path`만 갱신, 엔진이 방금 일으킨 이동이면 무시, 그 외(뒤로가기로 다른 화면 등)면 리셋.

## 새로고침 복원

- 칸 목록을 탭별 `sessionStorage`(`tile-panes`)에 저장. 다른 탭과 섞이지 않고, 탭을 닫으면 사라진다.
- 페이지 로드 시 저장된 `panes[0]`의 경로(쿼리 포함)가 지금 주소와 같으면 나머지 칸을 복원, 다르면(주소를 직접 입력 등) 버리고 전체화면.
- 서버는 첫 렌더에 주소창 칸만 그리므로 복원된 iframe 칸은 하이드레이션 직후 나타난다 (iframe 로딩과 같이 보여 깜빡임이 크지 않음). 읽기·쓰기 실패(사생활 보호 모드 등)는 무시하고 복원 없이 동작.

## 걷어내는 것

- `AuthSplitShell`의 왼쪽 홈 칸·위 칸 쌓기(`lib/authSplit.ts`의 `nextPrevious`·`closeDestination`)와 닫기. 로그인·가입 화면은 가운데 카드 한 칸만 그린다. 홈 | 로그인, 로그인 | 가입 분할은 엔진이 만든다.
- `TileLink`(쓰는 곳 없음): 모든 링크가 엔진을 타므로 불필요.
- 9/29의 "주소창 칸 경로가 바뀌면 서브 칸 비우기" — 위 동기화 규칙으로 대체.

## 테스트

- Vitest(`lib/`): 화면 표 매칭(구체적 경로 우선, 표에 없는 경로), `decideOpen` 전 경우(제자리·리셋·추가·가득 참·같은 화면 교체·로고·좁은 화면), 닫기(`panes[0]`·중간·마지막), 주소창 동기화, 저장 형식 복원(일치·불일치·깨진 값).
- 수동(브라우저): 홈 → 로그인 → 가입 → 검색 순서로 큐, 판매 화면 열 때 리셋, 각 칸 닫기, 새로고침 복원, iframe 칸 안 링크, 뒤로가기.

## 범위 밖

- 칸 크기 조절, 칸 순서 바꾸기, 4칸 이상.
- 모바일 분할.
- 판매·구매 등 아직 없는 화면 자체 (표에 경로만 미리 둠).
