# 내 판매글(검색형 화면 + 행 안 수정)·사용자 메뉴 개편 설계

2026-10-06. `2026-10-06-mypage-design.md`의 "마이페이지에 내 판매글 목록"과 "메뉴 항목 둘"을 대체한다 (PR #40 안에서 바꾼다, 브랜치 `feat/mypage`).
사용자와 대화로 정함: 판매글이 많아지면 단순 목록으로는 찾기 어렵다 → 검색 결과 화면과 같은 모양으로 내 글만.

## 정한 것

- 사용자 메뉴: 닉네임 + 배지 · [마이페이지] · [내 판매글] · [내 구매목록] · 구분선 · [로그아웃].
- `/my/listings` 내 판매글: 검색 결과 화면(`/search`)과 같은 검색창·필터·표/카드·[더 보기], 결과만 내 글.
- 표의 각 행 오른쪽 끝 [수정]. 누르면 그 행만 남고 표 맨 위, 칸이 그 자리 입력칸으로 바뀐다. 파일·긴 글 칸(상품설명·데이터시트·사진·대체품·테스트리포트·정품인증서)은 누르면 행 아래 빈 공간에 그 항목만 고치는 폼이 뜬다.
- 저장은 한 번에: [수정] 자리가 [저장]·[취소]로 바뀌고, [저장]은 처음 값과 달라진 것만 보낸다.
- 상품 칸(상품명·상품번호·제조사·제조일 등)도 고친다. 단 상품마스터는 다른 판매자 매물과 공유하므로 아래 "상품 칸 규칙". 상품마스터 목록에서 고르기는 상품마스터가 다 만들어진 뒤(사용자 지시 — 이번 범위 밖).
- `/my` 마이페이지는 허브: 사용자 카드 + [내 판매글]·[내 구매목록] 바로가기. 지금의 단순 목록(`MyListings`)과 이를 위해 늘린 `/mine` 응답 필드는 되돌린다(추가등록 고르기는 원래 필드만 씀).
- `/my/purchases` 내 구매목록: 구매 기능(구매요청·견적·발주)이 없어 빈 화면("아직 구매 기능이 없어요"). 구매 기능이 생기면 채운다.

## 화면: `/my/listings`

- 로그인 필요(`RequireLogin`). 레이아웃·폭·검색창·필터 바·결과 머리줄은 `/search`와 같다. 상태는 URL 쿼리(`/my/listings?q=…&status=…`)로 — 검색과 같은 `lib/search` 파싱·빌드를 경로만 바꿔 쓴다.
- 내 글 모드에서 다른 점: 체크박스·[견적 요청]·[구매] 없음, 거래상태 기본값 "전체", 빈 상태 "등록한 판매글이 없어요 + [판매상품 등록]", 마지막에 [수정] 열(고정 폭, 오른쪽 sticky).
- 행 클릭은 상세로(검색과 같음). [수정] 클릭은 상세로 가지 않는다.
- 모바일 카드(칸 폭 < 576): 행 안 수정은 하지 않고 [수정]이 기존 수정 화면 `/listings/{userId}/{regDate}/edit`로 간다 (좁은 카드에서 열 단위 편집은 못 씀).

### 행 안 수정 (표, 칸 폭 ≥ 576)

- 한 번에 한 행만 수정. 수정 중엔 다른 행·[더 보기]를 숨기고 그 행을 맨 위에. [취소]·[저장] 성공 시 목록으로 돌아오고 스크롤 위치를 되돌린다.
- 입력칸으로 바뀌는 열(표에 있는 열 그대로): 상품명·상품번호·제조사·제조일(date)·상품상태(구간 select)·불량지원(select)·보증기한 대신 보증기간(개월 select — 표는 보증기한을 보여 주지만 입력은 기간, 추가등록과 같은 규칙).
- 행 아래 폼으로 고치는 열: 상품설명(textarea), 데이터시트(PDF), 사진(최대 4), 대체품·테스트리포트·정품인증서(PDF·JPG·PNG). 열을 누르면 그 항목 폼이 행 아래에 뜨고, 다른 열을 누르면 그 폼으로 바뀐다(한 번에 하나). 폼 값은 [저장] 전까지 유지.
- 표에 없는 칸(단가·판매수량·재고·최소주문·주문단위·납기일)은 이번 범위 밖 — 상세의 [수정] 화면에서. 표 열 구성은 검색과 같게 둔다(사용자 지시 "똑같이").
- 검증은 등록·수정 폼과 같은 zod 스키마 수치(`docs/security.md` 입력 검증). 칸 오류는 칸 아래·폼 안에, 서버 `fields` 오류는 해당 칸에, 그 외는 행 위 한 줄. 업로드 중엔 [저장] 비활성.
- [저장]은 상품 칸 변경과 매물 칸 변경을 한 요청(PATCH)으로 — 한 트랜잭션에서 둘 다 되거나 둘 다 안 된다.

### 상품 칸 규칙 (서버)

상품마스터는 `(prod_name, prod_brand)` 유니크이고 같은 상품을 여러 매물이 공유한다.

1. 상품명이나 제조사가 바뀌면: 등록과 같은 `findOrCreate`로 그 이름·제조사의 상품을 찾아 **이 매물만** 그 상품으로 옮긴다. 있으면 그 상품 값(번호·제조일·스펙·카테고리)을 쓰고 응답으로 돌려줘 화면 칸을 채운다. 없으면 보낸 값으로 새로 만든다. 옛 상품은 그대로(남의 매물 영향 없음).
2. 상품명·제조사는 그대로이고 상품번호·제조일·스펙·카테고리만 바뀌면: 그 상품을 쓰는 매물이 **이 매물뿐이면** 상품마스터를 고친다. 다른 매물도 쓰면 422 `PRODUCT_SHARED` + 그 칸에 "다른 판매자와 같이 쓰는 상품 정보라 고칠 수 없어요".
3. 검증 수치는 등록과 같다(상품명·제조사 필수 50자, 번호 20자, 스펙 100자, 제조일 오늘까지, 카테고리 10자).

요청: `ListingUpdateRequest`에 상품 필드 `categoryCode·prodName·prodBrand·prodNo·prodMufcDate·prodSpecInfo` 추가(모두 선택, null = 그대로, `""` = 비우기 — 상품명·제조사·카테고리는 비울 수 없음). 기존 수정 화면(`/edit`)의 "상품마스터 칸은 읽기 전용"은 이 PR에선 그대로 둔다(그 화면은 행 안 수정의 모바일 대체 경로).

## API

- `GET /api/v1/listings?mine=true&…` — 검색 조건 그대로 + 요청자 본인 글만. 로그인 없이 `mine=true`면 401. 본인 id는 인증 정보에서만. 응답 `ListingPageResponse` 그대로(개인정보 없음).
- `PATCH /api/v1/listings/{userId}/{regDate}` — 상품 필드 추가(위 규칙). 소유자만(기존 403), 업로드 키 선점 규칙 그대로, rate limit 그대로.
- `GET /api/v1/listings/mine` — 원래 필드로 되돌림(추가등록 고르기 전용).

## 테스트

- 백엔드 API: `mine=true` 본인 글만·남의 글 제외·비로그인 401·검색 조건과 조합; PATCH 상품명 변경 → 기존 상품으로 연결 / 새 상품 생성, 남의 매물의 상품은 그대로; 번호만 변경 — 단독 사용이면 마스터 수정, 공유면 422 `PRODUCT_SHARED`; 상품+매물 칸 한 요청에서 하나가 실패하면 둘 다 안 바뀜; 남의 매물 403.
- 프론트 Vitest: 행 수정 값 ↔ PATCH 변환(바뀐 것만, 상품 칸 포함, 보증 개월↔일), `lib/search`의 `mine` 경로 빌드·파싱.
- E2E(#41): 마지막 단계를 "메뉴 → 내 판매글에서 방금 글이 보인다 → [수정] → 상품상태 바꾸고 [저장] → 반영"으로.
